# Встроенные шаблоны конфигураций

Каталог находится в `frontend/src/lib/templates/catalog.ts`, тексты Mihomo —
в `frontend/src/lib/templates/mihomo.ts`. Они включаются в сборку UI, поэтому
открытие каталога и импорт не требуют доступа к GitHub. Правила Mihomo и
Zashboard по-прежнему загружаются самим ядром из указанных в конфигурации URL.

Основа каталога — [шаблоны zxc-rv/assets](https://github.com/zxc-rv/assets/tree/main/config_templates),
снимок от 11 октября 2026 года. Изменения каталога обновляются вместе с проектом,
после проверки diff и тестов; обновления внешней ветки `main` автоматически
в конфигурацию пользователя не попадают.

## Импорт

1. Откройте «Утилиты → Шаблоны конфигураций».
2. Выберите шаблон и файл назначения. Для Xray доступны файлы с нужным
   разделом и пустые JSON-объекты/файлы; для Mihomo — основной `config.yaml`.
   Если файл ещё не существует, создайте его в редакторе.
3. Для Xray Routing выберите существующий прокси-outbound. Проверяются
   уникальность используемых тегов, типы `direct`/`block` и наличие нужных
   доменных/IP-геофайлов на текущем роутере. Категории внутри `.dat` проверяет
   ядро при «Применить». При ошибке проверки геофайлов повторите предпросмотр.
4. Просмотрите текст до и после импорта, затем нажмите «Вставить в редактор».
   Несохранённые изменения входят в текст «До импорта».
5. Сохраните или примените конфигурацию обычным способом. Сам импорт ничего
   не записывает на роутер и не перезапускает сервис. «Сохранить» проверяет
   синтаксис редактором; «Применить» дополнительно проверяет конфиг ядром.

В Xray заменяется только выбранный раздел; комментарии и остальные разделы
вне заменяемого блока сохраняются. Routing сохраняет `domainStrategy`,
балансировщики и другие параметры, заменяя только `rules`. Outbounds добавляет
отсутствующие `direct`/`block`, сохраняя серверы и учитывая другие открытые
конфиги. Policy удаляет `uplinkOnly`/`downlinkOnly` уровня 0, возвращая стандартные
таймауты установленного ядра; другие параметры политики сохраняются.

В Mihomo по умолчанию сохраняются `proxies`, `proxy-providers`, `dns` и настройки
доступа к API. Пользовательские группы и rule-providers, отсутствующие в шаблоне,
также сохраняются, чтобы не потерять зависимости подключений/DNS. Одноимённые
группы и провайдеры правил шаблона заменяют старые определения. Ссылки YAML
раскрываются в значения, поэтому сохранённый DNS не зависит от расположения
исходных anchors; комментарии в перенесённых разделах могут измениться.
Полная замена доступна при отключении сохранения настроек и всегда показывается
в предпросмотре. Если прокси нет, добавьте подключение после импорта.

Блокировки QUIC (UDP/443) и рекламы включаются отдельно, по умолчанию отключены.
Отключение опции не отменяет блокировки, заданные другими пользовательскими
правилами или внешними списками. Провайдер отключённой блокировки сохраняется,
если на него ссылаются перенесённые DNS или подправила.

Предпросмотр привязан к ядру, пути, тексту и ревизии файла. Для Xray дополнительно
фиксируются остальные открытые конфиги. При изменении любого из них предпросмотр
нужно подготовить заново. Переключение вкладок не меняет файл назначения.
Проверка геофайлов относится к текущему роутеру; при массовом применении
совместимость конфигурации на каждом роутере проверяется его ядром.

## Обновление каталога

Не заменяйте встроенные шаблоны результатом сетевой загрузки во время импорта.
Для обновления сравните источники с локальными текстами, сохраните метаданные
`id`, `core`, `section`, проверьте ссылки на группы, провайдеры и геофайлы.
Изменения политики маршрутизации и требований к версии ядра должны быть
описаны в release notes при выпуске новой версии.

Минимальные проверки из `frontend`:

```sh
bun test tests/templates.test.ts tests/config-save.test.ts tests/xray-gui-save.test.ts
bun run build
bun run lint -- --max-warnings 0
```

Дополнительно проверьте импорт и применение на поддерживаемых версиях Xray/Mihomo
с тестовыми подключениями и геофайлами. Парсинг JSON/YAML и проверки связей
не заменяют запуск `xray -test` / `mihomo -t`.
