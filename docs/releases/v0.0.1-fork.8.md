# v0.0.1-fork.8 — проверка загрузок и безопасное сохранение конфигов

Изменения относительно v0.0.1-fork.7. Канал выпуска: prerelease.

## Исправления

- R12: установка и обновление панели, ядер и yq проверяют SHA-256 до распаковки, запуска и замены. Источник доверия — метаданные, полученные напрямую по HTTPS от GitHub API без прокси и перенаправлений. Загрузка бинарника через gateway допустима, но его хеш должен совпасть с независимыми метаданными. Если API недоступен, хеш отсутствует или не совпадает, установка прекращается.
- Установщик больше не подбирает локальный файл из /opt/tmp автоматически. Локальному файлу доверяют только в явно выбранном ручном режиме --local, --file или --rollback. Для сетевой установки через shell требуются jq и sha256sum. Подробности: docs/update-integrity.md.
- R15: диагностика classical-провайдеров Mihomo отклоняет MATCH, RULE-SET и SUB-RULE, в том числе внутри логических выражений. Глубина парсинга и оценки ограничена; циклы провайдеров возвращают Unknown вместо бесконечной рекурсии. Последующие правила продолжают проверяться.
- R16: конфиги создаются и сохраняются через staged write, синхронизацию и атомарную замену. При ошибке commit выполняется откат; если откат не удался, сохраняется резервная копия и сообщается её путь. Права доступа и символические ссылки сохраняются. Общая блокировка охватывает snapshot Xray, validation и commit, а также другие операции редактора, запись из DNS и восстановление бэкапа. Неполный snapshot запрещает сохранение; отмена HTTP-ожидания не прерывает транзакцию. Validation ограничена 30 секундами.
- R17: после успешного завершения init start/restart сервер ждёт три секунды и проверяет процесс выбранного ядра. Exit 0 без запущенного процесса возвращает ошибку. Проверка ненулевых exit status, добавленная ранее, закреплена регрессионными API-тестами.
- В REVIEW.md закрыты R12, R15, R16 и R17. Закрыто 14 из 36 подтверждённых пунктов, 22 остаются открытыми.

## Проверки

- Backend: cargo check без предупреждений; cargo test и cargo test --features local-dev — по 246 успешных тестов, 2 теста с внешними MMDB-файлами штатно пропущены.
- Frontend: установка по frozen lockfile, 16 успешных тестов, production-сборка и ESLint без ошибок и предупреждений.
- Регрессионные проверки охватывают недоверенные и недоступные метаданные, подмену загрузки, ручной локальный режим, вложенные classical-правила и циклы, ошибки записи/sync/rename, откат и recovery-копию, конкурентное сохранение, отмену запроса и ошибки запуска ядра.
- CI повторяет shell-проверки, frontend и backend-тесты, собирает ARM64, MIPS и MIPSel без local-dev. После публикации сверяет GitHub SHA-256 всех трёх бинарников с результатами сборки.

## Ограничения

Это prerelease. Реальный роутер, браузерный E2E, отключение питания и файловая система целевого устройства не проверялись. Проверка запуска подтверждает наличие процесса, а не доступность сетевых портов.

SHA-256 из GitHub API не является цифровой подписью: сохраняется доверие к HTTPS, GitHub и аккаунту издателя. Недоступность прямого API блокирует обычную сетевую установку, даже если бинарник доступен через gateway. Ручные локальные режимы требуют доверия пользователя к выбранному файлу.

R09 (порядок применения DNS), R21 (атомарность восстановления целого бэкапа) и остальные открытые пункты REVIEW.md не исправлены этим выпуском. Общая блокировка предотвращает вмешательство восстановления бэкапа в validation редактора, но не превращает восстановление всего архива в атомарную операцию.
