# v0.0.1-fork.14 — защищённое управление флотом, fail-closed авторизация и маршрутизация Mihomo

Изменения относительно v0.0.1-fork.13. Канал выпуска: prerelease.

## Исправления

- **R02 (Безопасная авторизация по умолчанию и fail-closed при сбоях настроек):**
  - Значения настроек авторизации по умолчанию переведены в защищённый режим (`enabled: true`). До первичной настройки пароля панель не оставляет открытый административный доступ.
  - Устранена уязвимость fail-open при повреждении файла настроек: функции `load_settings` и `parse_settings` при любых ошибках чтения или парсинга `xkeen-ui.json` принудительно включают авторизацию (`auth.enabled = true`). Если блок `auth` уцелел, учетные данные и сессии сохраняются, а повреждённые второстепенные секции нормализуются; если файл повреждён полностью, доступ без авторизации блокируется.
  - В CLI бэкенда добавлен параметр `-H, --host` для явной привязки веб-интерфейса к конкретному IP-адресу (например, loopback или доверенный LAN-интерфейс).
  - Реализована поддержка авторизации через заголовки `Authorization: Bearer <token>` и `X-Auth-Token: <token>`, возвращающие токены при входе и первичной настройке.

- **R03 (Защищённое управление парком роутеров и поддержка HTTPS):**
  - Добавлена поддержка защищённого протокола HTTPS для удалённых роутеров флота (`protocol: 'http' | 'https'`). Функция `routerBaseUrl` и запросы строятся с выбранным протоколом, предотвращая передачу открытого трафика и ошибки mixed-content при работе из защищённых панелей.
  - Реализована аутентификация устройств флота: в модель `RemoteRouter` добавлено поле `token`. Все межхостовые административные запросы (`apiCall`) автоматически передают заголовок `Authorization: Bearer <token>`.
  - Снято требование отключать авторизацию на удалённых роутерах: фильтрация массовых операций (`isRouterSelectable`, `filterAuthBlockedTargets`) допускает роутеры с включённой авторизацией при наличии заданного токена.
  - В диалоге добавления роутера реализован выбор протокола и ввод токена доступа, а индикатор статуса роутера визуально дифференцирует доступные защищённые роутеры и роутеры, требующие ввода токена.

- **R29 (Корректный учёт режимов Direct и Global в тестере маршрутов Mihomo):**
  - В движок тестирования маршрутизации внедрён типизированный enum `MihomoMode` (`Rule`, `Global`, `Direct`), считываемый из `config.yaml`.
  - Семантика маршрутизации приведена в строгое соответствие с ядром Mihomo: в режиме `Direct` трафик безусловно направляется в `DIRECT`, в режиме `Global` — в `GLOBAL`, минуя правила.
  - Реализован опрос live runtime API работающего ядра (`GET /configs`) и формирование предупреждений в результатах диагностики при расхождении runtime-режима с файлом на диске либо активности режимов `Global`/`Direct`.

- **R36 (Инвалидация кэша просмотрщика при массовом обновлении провайдеров):**
  - Кэш содержимого провайдеров вынесен в модуль `frontend/src/lib/providersCache.ts` с функцией инвалидации `invalidateProviderContentCache`.
  - В `updateAllProviders` операции обновления отслеживаются через `Promise.allSettled`, и кэш просмотрщика гарантированно инвалидируется для каждого успешно обновлённого провайдера.

- Закрыты последние подтверждённые пункты `REVIEW.md` (R02, R03, R29, R36). Все 36 подтверждённых пунктов первоначального аудита (R01–R36) закрыты.

## Ограничения

Это prerelease. Реальные роутеры и нагрузочное тестирование сотен устройств не проверялись; smoke-тесты через runner cross и эмуляцию не заменяют физических приёмочных испытаний на целевом парке.
Гипотезы H02–H05 остаются без изменения статуса и требуют проведения натурных тестов. Готовность к массовой корпоративной эксплуатации без предварительных полигонных испытаний на конкретном парке роутеров не заявляется.
