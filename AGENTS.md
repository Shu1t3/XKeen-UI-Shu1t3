# Правила релизов

- Для каждой новой версии обязателен файл `docs/releases/<tag>.md`, где `<tag>` точно совпадает с тегом релиза.
- Описание на русском языке должно объяснять, какие исправления привели к выпуску версии и что изменилось для пользователя. Перечень хешей или пустая автогенерация не заменяют описание.
- Включать изменения с предыдущего релиза, результаты проверок и существенные ограничения. Не заявлять об исправлении открытых пунктов REVIEW.md.
- Публиковать содержимое этого файла в GitHub Releases, чтобы оно было доступно в истории версий. Не выпускать релиз с пустым описанием.
- Перед коммитом и публикацией должны проходить сборка frontend, ESLint без ошибок и предупреждений, backend-тесты. Бинарники роутеров собирать без `local-dev` для всех поддерживаемых архитектур.
- Сохранять выбранный канал релизов; переход из prerelease в stable согласовывать с пользователем.
